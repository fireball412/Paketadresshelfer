# Sicherheitsprobleme melden

Veröffentliche keine echten Adressen, Zugangsdaten oder sonstigen persönlichen
Daten in Issues, Pull Requests oder Anhängen.

Für eine nicht sensible Fehlermeldung verwende die Issue-Vorlage mit erfundenen
Beispieldaten. Für eine Sicherheitslücke verwende die private GitHub-Funktion
**Report a vulnerability**, sofern sie im Repository aktiviert ist. Falls sie
nicht angeboten wird, veröffentliche keine ausnutzbaren Details oder vertraulichen
Daten in einem öffentlichen Issue.

Dieses private Open-Source-Projekt hat keine zugesicherte Reaktionszeit oder
garantierte Wartungsdauer. Bekannte erhebliche Einschränkungen sollen in der
README beziehungsweise den Release-Hinweisen dokumentiert werden.
